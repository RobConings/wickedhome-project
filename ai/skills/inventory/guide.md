- Products: inventory_prepare_product; reuse catalogue/alternatives. Verify photo/page/shop/price/barcode/package; missing shop → shops_save. Re-read saved links/offers, disclose gaps. Never invent facts. inventory_products: follow nextOffset while hasMore.
- Central units: inventory_units reads the household-wide catalogue, reference relationships, aliases, purchase rounding and updatedAt; optionally checks quantity/fromUnit/toUnit. Definitions are independent of products. Use the verified result, not arithmetic invented from labels. Examples such as 1 bottle = 75 cl or a head's weight are possible definitions, never defaults. Different sizes need distinct names. A bag is not one piece. Counting stock requires no gram weight.
- inventory_save_units replaces the whole catalogue. Read inventory_units first, preserve unrelated entries, pass its exact updatedAt as expectedUpdatedAt, and confirm the actual added/changed/removed definitions and rounding. Never invent ratios. The shared service rejects stale revisions, invalid references and cycles. It changes no stock quantities. Children read only.
- inventory_units includes overview with all built-in, custom and already-used units (aliases grouped, undefined container content marked). usedUnits are household-scoped names from products, stock, recipes, shopping and purchases, not verified conversions. Give fromUnit alone for permitted relationships with ratios and direct/indirect paths. units contains editable household definitions AND built-in end-unit settings: preserve both, never copy the full overview/usedUnits into inventory_save_units. The settings page offers the same explorer.
- End units: isTerminal=true allows the unit as either endpoint but forbids it inside a path, including between sibling branches. box → piece and piece → bag can each be valid, but box → piece → bag is blocked if piece is terminal. This applies to recipes, cooking, aliases, package bridges and MCP conversions; never bypass it with manual arithmetic or by saving a shortcut. inventory_units reports conversion.blockedByTerminal for these pairs. Default false preserves existing behaviour. For a built-in end-unit setting, use its canonical overview name, referenceUnit = overview.referenceUnit or its own name for a root, its unchanged factor/rounding, aliases: [], isTerminal: true; remove that settings record (or set false) to restore transit. Standard ratios/aliases cannot be changed. Custom unit isTerminal is stored on its existing definition. There can be 100 custom definitions plus built-in settings.
- Shared stock: 1 jar/pack = 1 stock unit, even if linked brands differ in package weight. inventory_link_alternative preserves product identities but links ONE shared stock, counted once per location. Already-linked products bring ALL alternatives along: show every affected product, obtain explicit agreement, then set confirmGroupMerge=true. Never silently join groups. Linking adds no purchase.
- Stock/history: inventory_stock; low/expiry: inventory_low_stock. Below minimum = out; essential at minimum = out; nonessential at minimum = nearly_out. These are forecasts, not necessarily zero stock. The person decides what to buy. inventory_change_stock use/set; inventory_save_stock_item minimum/expiry. Children use/add; adults count/manage.
- Goods: inventory_purchases → inventory_record_purchase with stable source, or inventory_record_purchase_batch for new reports/chat images. Ask unclear counts/places. Shopping ticks may already credit stock: link existing acquisitions, never add twice. Session goods/receipt: use shopping_session_match_receipt instead.
- Receipts: uploaded document, printed line, actual date/shop. Ask same/extra or already counted; never infer. Review conflicts individually. Movements: inventory_purchase_history.
- Recipes: recorded 0 is empty in every unit, even when no conversion exists. Positive unknown_amount is not a shortage. recipes_list exposes comparable, stockEmpty, purchaseUnit and purchaseQuantityRequired; ask for an explicit purchase quantity if required, then recipes_plan quantities. Never substitute 1 kg/package. recipes_plan adds needs; recipes_use consumes. Stock null means untracked, not a confirmed zero.
- Physical counting may skip a location until its stock next reaches 0; this persists between rounds and can be undone. Exclusion never changes quantity or shopping minima. A manual shopping need is separate from a count.

- inventory_product_context: linked needs/tasks/projects; purchases_list productId: existing history, no stock write.
